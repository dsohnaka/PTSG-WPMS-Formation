## Details / 詳細

### SD-01 — Band on the issue port / 発行ポートの帯域

- **Texts.** Master Ch.5 §5.2 (lane 1 "Issue port {mode, sub-op, operand, band} + valid"), §5.3 ("the Core presents {mode, sub-op, operand D16–D31, current band}"), §5.8 (E2 is Formation-detected).
- **Found.** Frozen `ptsg_core.v` (sha256 `fb995687…60e0`), port list: `ext_op_valid`, `ext_op_subopcode` (= D4–D7), `ext_op_sub_operand` (= D8–D15), `ext_op_data` (= D16–D31), `ext_op_ready` (captured, never stalled on). The band exists only as internal `window_open` / `in_queued_band`.

### SD-05 — R1's forward conditional and the NONEMPTY check / R1 の前方条件遷移と NONEMPTY 判定

### SD-16 — The Maclaurin core / マクローリン・コア *(Phase 4)*

- **Texts.** Customer Ch.2 v1.1: §2.2.4 adopts Approach B (2 clocks per stage, "constant absorption", "+4 bits"); §2.4.1 gives the formats — x′ Q2.25, X Q4.23, every Horner intermediate and every constant C₃…C₁₁ Q1.26; §2.5.1 "Y₁ = (1/362880) − X · (1/39916800), pre-scaled"; §2.8.2 aggregate error ≈ 1.3×10⁻⁷; C2-D10 seven 27×27 multipliers; §2.3.3 "bit-inversion of the 30-bit field, equivalent to two's complement negation modulo 2⁻²". The 2026-04-29 trace describes Approach B as the Ohnaka refactoring `x·(1 − x²/6·(1 − x²/20·(…)))` with (2π)² absorbed. The customer's oracle has no sin function (it fixes exp2, amplitude, phase and the glide bit for bit).
- **Found (ORACLE).** The table read literally cannot meet the budget: C₁₁ = 2⁻²⁶·2 (1.68 rounds to 2: +19 %), C₉ = 185·2⁻²⁶; max |error| over 200,000 phases **3.97×10⁻⁷ = 2⁻²¹·²⁶**. Two's-complement negation maps ξ = 0 of Q2 to ξ′ = 0, i.e. sin(π/2) = 0 (the RTL uses bit inversion; mutant S1 shows the difference is caught). The truncation error at π/2 is (π/2)¹³/13! = 5.69×10⁻⁸, not ≈ 4×10⁻⁸.
- **Realization (Arena, published).** `hw/tools/l1_model.py` `sin_q040` = `hw/l1/wpms_l1_sin.v` bit for bit: u = ξ′ ≫ 4 (26 bits, 2⁻²⁸ cycle); U = u² ≫ 26; S₅ = c₄ − (U·c₅ ≫ 32), S₄ = c₃ − (U·S₅ ≫ 31), S₃ = c₂ − (U·S₄ ≫ 30), S₂ = c₁ − (U·S₃ ≫ 29), S₁ = c₀ − (U·S₂ ≫ 27), sin = u·S₁ ≫ 11 (Q0.40), c_j = (2π)^(2j+1)/(2j+1)! at scales 2²³, 2²⁰, 2¹⁹, 2¹⁹, 2²⁰, 2²² — seven multipliers, all operands ≤ 26 bits, 16 clocks. Max |error| **5.96×10⁻⁸ = 2⁻²⁴·⁰⁰**, exhaustive over u (2²⁶ values, both ends of each u's 16 phases). The Ohnaka refactoring would need a second multiplier per stage for no gain here: the per-stage scales already give every stage 25–26 significant bits.

### SD-20 — The ROM's list against ownership / ROM の書込み列と所有 *(Phase 5)*

- **Texts.** Ch.5 §5.8: the ROM (port 3) "holds a short list of (address, data) writes ending in GO_ALL"; its initial content writes module 0 block 0 with the full mask, the SWEEP words, MG_TARGET = 0 and "all owners = port 0". §5.5.2: "A write, arm or GO from a non-owner is rejected and counted in REJECT[port] … GO_ALL (port 0 or 3 only) fires every armed item. Changing an owner disarms that item."
- **Found (reading).** If owners start at port 0, the ROM's writes to block 0 are refused; if the ROM sets "all owners = port 0" before its GO_ALL (the list ends in GO_ALL), it disarms its own items. The list works only if port 3 is exempt from ownership for its own writes, which the text does not say.
- **Realization.** The minimal switch builds ports 0 and 3 — the two privileged ports. OWNER[m] is stored and read back; ownership is not enforced and a change of owner disarms nothing (with ports 0 and 3 only, no transaction would be refused by it). Enforcement belongs with port 1 or 2.
- **Disposition (proposed).** Customer to state the ROM's standing: port 3 exempt from ownership for its own list (proposed), or owners written first with no disarm of the ROM's own items.
- **和文.** ROM（ポート 3）の書込み列は、ブロック 0 の書込み・「全所有者 = ポート 0」・最後に GO_ALL を含むが、§5.5.2 の所有規則（非所有者の書込み拒否、所有者変更で disarm）と字義どおりには両立しない。最小スイッチは特権ポート 0・3 のみなので OWNER は保持・読出しのみで施行しない。ROM の扱いの明記を顧客へ提案。

### SD-21 — "Armed" means two things / 「構え」の二義 *(Phase 5)*

- **Texts.** Ch.5 §5.4.2: stage, **arm** (COMMIT with the arm bit), go (GO), acknowledge; §5.4.3: "A GO is latched and handed to all Formations on the next synchronized strobe … GO → first sweep playing it: ≤ 2 sample periods". Map v0.3 §7: "At each synchronized strobe the sequencer latches the take-set: the blocks and sweep item **armed** at that moment."
- **Found.** Read with Ch.5's meaning, Map v0.3 §7 would take items armed but not yet fired. The profile's "armed" must mean *handed over by a GO*. Realized that way: the switch keeps the writer's arm and hands over the fired set; the Formation's flags are written in one clock (RH004: inbox port 0x9F), so a strobe takes all of a GO or none. The Phase 5 timing case (hand-overs presented from 3 clocks before to 3 clocks after a strobe) then found that a registered hand-over presented in the strobe clock itself missed that strobe: a GO accepted in the clock before a strobe played from the third strobe (2 periods + 1 clock). RH004 therefore also lets the take-set include an arm write presented in the strobe's own clock: every GO now plays from the second strobe after its acceptance (RTL-SIM: 960 GOs over fifteen runs; the timing case puts hand-overs at every offset from −3 to +3 clocks around a strobe, 62 at each budget, all heard).
- **Disposition (proposed).** Map v0.3 §7 at its next version: "the items handed over (fired) at that moment, a hand-over in the strobe's own clock included".
- **和文.** 第 5 章の「構え」は GO 前の段階、Map v0.3 §7 の「構えられた項目」は GO で引き渡された項目の意味でなければならない。スイッチは構えを保持し、発火した集合を 1 クロックで Formation に渡す（RH004）。さらにタイミング試験で、ストローブ直前に受理された GO が 3 番目のストローブまで遅れる（2 周期 + 1 クロック）ことを見つけ、ストローブのクロックに提示された書込みも取込みに含めるようにした。いまはすべての GO が受理後 2 番目のストローブから鳴る。
