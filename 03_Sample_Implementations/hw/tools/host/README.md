# hw/tools/host — OUTSIDE WPMS: a stand-in for the Layer 4 controller / WPMS の外：第 4 層制御器の代役

**Nothing in this folder is part of the WPMS design.** These tools stand in for the Layer 4 verification tool (customer Ch.5 §5.7) until it exists. They talk to the input switch the way any writer does, through the address map of Ch.5 §5.6, integers only (C3-D1).

**このフォルダの中身は WPMS の設計の一部ではない。** 第 4 層の検証ツール（顧客 第 5 章 §5.7）ができるまでの代役で、どの書き手とも同じく、第 5 章 §5.6 のアドレスマップを通して整数だけで話す。

## The protocol (by hand, in the Quartus In-System Sources and Probes Editor) / 手順（Quartus の ISSP エディタで手動）

**Source HOST, 48 bits, hex `C AAA DDDDDDDD`:**
- C = {0, 0, RD, WR};
- AAA = the word address (Ch.5 §5.6);
- DDDDDDDD = the data.

**Probe HOST, 36 bits, hex `S RRRRRRRR`:**
- S = {0, REJ, RD_ACK, WR_ACK};
- RRRRRRRR = the word read (after a write: the word read back).

**Write:** type the address and the data, and flip WR in the same edit. For example, from `0 000 00000000`, `1 290 00000031` writes SWEEP = {P = 1, order 3}. When WR_ACK equals WR the write has happened. REJ = 1 means the switch refused it: the item was frozen while armed, a GO failed its check, or the word is read-only or unmapped. REJECT[0] (0x030) counts refusals.

**Read:** type the address and flip RD; when RD_ACK equals RD, R is the word.

**Nothing happens while WR = WR_ACK and RD = RD_ACK**, so the address and data can be edited freely before the flip.

| Some words | Address |
|---|---|
| INBOX[b][i] (module 0) | 0x200 + 0x10·b + i |
| RTOUT[b] | 0x280 + b |
| COMMIT[b] ([15:0] mask, [16] RT.OUT, [30] arm, [31] go-now) | 0x288 + b |
| SWEEP ([3:0] P, [27:4] order) | 0x290 |
| SWEEP_COMMIT ([30] arm, [31] go-now) | 0x291 |
| GO ([0] GO, [1] GO_ALL) | 0x008 |
| GO_SEQ / APPLIED_SEQ / APPLIED_SAMPLE | 0x009 / 0x00A / 0x00B |
| MG_TARGET / MG_RATE / G_CTRL / MUTE | 0x010 / 0x011 / 0x013 / 0x015 |
| TEST_ORIGIN (write 1 = KEY[1]) | 0x01C |
| REJECT[0] (write 1s to clear) | 0x030 |

The live probes need no transaction:
- **STAT** (128 bits): MG, STROBE_INTERVAL, G_EFF, SWEEP_CLOCKS, CLIP, the error flags, GO_SEQ and APPLIED_SEQ (low bytes), the frozen items, REJECT[0/3] (low bytes).
- **INSP** (96 bits): the inspector's phase, level and amplitude.

The bit layout is in `hw/switch/wpms_system.v`.

**書込み**：アドレスとデータを入れ、同じ編集で WR ビット（ソースの bit 44）を反転する。WR_ACK が WR と等しくなれば完了。REJ = 1 は拒否（構え中で凍結、GO の検査不合格、読出し専用／未割当）。**読出し**：アドレスを入れて RD（bit 45）を反転し、RD_ACK が RD と等しくなれば R が値。トグルを反転しない限り何も起きないので、アドレスとデータは自由に編集してよい。

## What was run here, and what waits for the board / ここで走らせたもの・実機を待つもの

Quartus is not available here, so the scripts have **not run against Quartus**; Phase 6 runs them on the board. They did run under tclsh 8.6 against the stand-ins (`check_host_tcl.py`: all cases pass, and each of eight deliberately broken copies of `wpms_issp_host.tcl` is caught). The command names and arguments are those of Quartus Prime's `::quartus::insystem_source_probe` package as the stand-ins model it: if Quartus answers differently (for example the order of the fields of `get_insystem_source_probe_instance_info`), Phase 6 finds it at `wpms_open`. What the scripts send is checked twice: under tclsh (the transactions) and in RTL-SIM (the same steps through the identical bit protocol, `cosim_switch.py --case music`).

ここには Quartus がないため、Quartus に対しては**まだ走らせていない**（Phase 6 で実機に対して走らせる）。代わりに、ISSP コマンドの代役に対して tclsh 8.6 で走らせ（`check_host_tcl.py`、全項目合格）、わざと壊した `wpms_issp_host.tcl` 8 種もすべて検出された。コマンド名と引数は Quartus Prime の `::quartus::insystem_source_probe` パッケージを代役がなぞったもので、Quartus の応答が異なれば（たとえば `get_insystem_source_probe_instance_info` の欄の順）Phase 6 の `wpms_open` で分かる。送る内容は二重に検査済み：tclsh でトランザクションを、RTL-SIM で同じ手順を同一のビット手順で。
